BLE Simulator 使用说明

系统概览

BLE 骑行设备模拟器：通过真实蓝牙广播，向骑行 App（Zwift / 行者 / Strava 等）模拟 FTMS 骑行台、功率计、速度踏频计、心率计。

  • MCP MCP 服务：HTTP JSON-RPC 接口，供 AI Agent / 脚本控制，跟随 Docker 持续运行
  • Dashboard 本页面：可视化控制台，与 MCP 共享同一份数据库持久化数据
  • Skill 操作文档：/skill/SKILL.md

关键约定：MCP 服务状态与模拟设备状态是两个独立维度 —— MCP 服务跟随 Docker 一直在线；模拟设备是否运行由你通过 Dashboard 或 MCP 控制。

数据持久化

所有模拟控制参数写入 SQLite（Docker 卷 ble-data），Dashboard 与 MCP 共享同一份数据：

  • 「模拟控制」页表单填好后点 启动 / 保存配置 → 写入数据库（sessions 表）
  • 刷新页面或点 载入已保存配置 → 从数据库回填表单（MCP 的 ble_get_config）
  • MCP 端 ble_start 不带参数时，也复用数据库里最近一次会话配置

动态模拟

功率/踏频/速度拟真波动 + 物理速度模型（体重/车重/滚动阻力/风阻）。autoStart 开启后无需 App 发 Start 即开始骑行。

骑行场景

  • steady 平稳 · freeride 自由骑 · intervals 间歇 · warmup_main_cooldown 热身-主课-冷却 · ride_script 骑行剧本（阶段序列，可循环）

连接方式

手机 / 骑行 App 搜索蓝牙设备名（广播名），连接后即可收到数据。连接失败时可尝试在 App 中删除设备重新搜索（会话变化会导致序列号变化，需重新发现）。

提示：模拟器通过宿主机 BlueZ 广播。若 App 能搜到但连接失败，检查宿主机 D-Bus 策略与 BlueZ 版本（≥ 5.87）。

MCP 接入（AI Agent / 脚本）

HTTP 端点：/mcp（本页同源）或 :3300/mcp

可用工具：ble_start / ble_stop / ble_restart / ble_status / ble_configure / ble_get_config / ble_set_interaction / ble_clear_interactions / ble_list_sessions / ble_get_session / ble_get_logs

详细协议见 /skill/SKILL.md。
